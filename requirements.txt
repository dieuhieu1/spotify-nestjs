# SECTION 4: AUTHENTICATION & SECURITY
# ============================================================

[AUTH-01] JWT Token Generation
  - Algorithm: HS512 (HMAC-SHA512)
  - Access Token payload:
      sub: user email
      iss: user name
      iat: issued at (timestamp)
      exp: expiry (15 minutes default)
      scope: space-separated "ROLE_USER CREATE_SONG DELETE_SONG ..."
      jti: UUID v4 (for blacklist tracking)
  - Refresh Token payload:
      Same claims, exp = 20 days
  - Reset Password Token payload:
      Same claims, exp = 15 minutes

[AUTH-02] JWT Verification (Custom Decorator/Guard)
  - Verify HS512 signature
  - Check token expiration
  - Check jti against InvalidatedToken table (blacklist)
  - Throw UNAUTHENTICATED if any check fails

[AUTH-03] Scope/Authority Building
  - buildScope(user): string
  - Format: "ROLE_USER ROLE_PREMIUM CREATE_SONG DELETE_SONG ..."
  - Concat role names with "ROLE_" prefix + permission names

[AUTH-04] JwtAuthGuard
  - Extends PassportStrategy(Strategy, 'jwt')
  - Validates token, attaches user to request
  - Used on protected routes

[AUTH-05] RolesGuard / PermissionsGuard
  - @Roles('ADMIN') decorator
  - @Permissions('CREATE_SONG') decorator
  - Guard checks JWT scope claim

[AUTH-06] Public Routes (no auth required)
  - POST /v1/auth/login
  - POST /v1/auth/register
  - POST /v1/auth/refresh-token
  - POST /v1/auth/forgot-password
  - POST /v1/auth/forgot-password/verify-code
  - POST /v1/auth/forgot-password/reset-password (note: original is change-password path)
  - POST /v1/auth/logout
  - POST /v1/payment/vn-pay-callback
  - GET /v1/search-by-priority
  - GET /v1/albums, /v1/albums/search
  - GET /v1/artists, /v1/artists/search
  - GET /v1/genres, /v1/genres/:id/songs
  - GET /v1/playlists, /v1/playlists/search
  - GET /v1/songs, /v1/songs/search
  - GET /v1/songs/:id, /v1/albums/:id, /v1/artists/:id, /v1/playlists/:id
  - Swagger docs

[AUTH-07] Password Hashing
  - Use bcrypt with saltRounds = 10
  - On register: hash password before storing
  - On login: compare plain password with hash

[AUTH-08] Refresh Token Storage
  - Store refresh token string + expiryDate in tbl_refresh_token
  - On refresh: verify token exists in DB and is not expired
  - Scheduled cleanup: daily at midnight, delete expired refresh tokens

[AUTH-09] Token Blacklist (Invalidated Tokens)
  - On logout: store JWT jti + expiry in tbl_invalidated_token
  - On every request: check jti not in blacklist

# SECTION 7: BUSINESS LOGIC
# ============================================================

[BL-01] Registration Flow
  1. Validate email uniqueness
  2. Validate password matches confirmPassword
  3. Hash password with bcrypt (rounds=10)
  4. Assign default USER role
  5. Save user to DB
  6. Generate access token + refresh token
  7. Save refresh token to DB
  8. Send welcome email asynchronously
  9. Return TokenResponse

[BL-02] Login Flow
  1. Find user by email, throw UNAUTHENTICATED if not found
  2. Compare password with bcrypt, throw UNAUTHENTICATED if mismatch
  3. Generate access token + refresh token
  4. Save refresh token to DB
  5. Return TokenResponse

[BL-03] Logout Flow
  1. Verify access token is valid
  2. Store jti + expiry in InvalidatedToken table (blacklist)
  3. Return void

[BL-04] Refresh Token Flow
  1. Verify refresh token signature and expiry
  2. Check refresh token exists in tbl_refresh_token and not expired
  3. Get user from sub claim (email)
  4. Generate new access token
  5. Return new TokenResponse

[BL-05] Change Password Flow
  1. Get current user from JWT
  2. Verify oldPassword matches stored hash
  3. Validate newPassword == confirmPassword
  4. Hash new password
  5. Update user in DB
  6. Return updated UserResponse

[BL-06] Forgot Password Flow
  1. Receive email
  2. Find user by email, throw error if not found
  3. Generate 6-digit numeric verification code
  4. Set expiry = current time + 10 minutes (unix timestamp in minutes)
  5. Save VerificationCode to DB
  6. Send verification code via email
  7. Return VerificationCode entity

[BL-07] Verify Code Flow
  1. Find VerificationCode by email + code
  2. Check not expired (compare expirationTime with current time in minutes)
  3. Generate reset password JWT token (15 min expiry)
  4. Save ForgotPasswordToken to DB (email + token + expiry)
  5. Return ForgotPasswordToken entity

[BL-08] Reset Password Flow
  1. Find ForgotPasswordToken by token string
  2. Verify JWT reset token is valid and not expired
  3. Validate newPassword == confirmPassword
  4. Hash new password
  5. Update user password in DB
  6. Delete ForgotPasswordToken from DB
  7. Delete all VerificationCodes for that email
  8. Return void

[BL-09] Song Counter (Listener)
  - Every GET /songs/:id increments song.listener by 1
  - This is a counter for popularity tracking

[BL-10] Album Counter (Follower)
  - Every GET /albums/:id increments album.follower by 1

[BL-11] Artist Counter (Follower)
  - Every GET /artists/:id increments artist.follower by 1

[BL-12] Playlist Counters (Follower + Listener)
  - Every GET /playlists/:id increments both playlist.follower and playlist.listener by 1

[BL-13] Save Playlist (User)
  - Add playlist to user's savedPlaylists (many-to-many)
  - Increment playlist.listener by 1
  - Return PlaylistResponse

[BL-14] Album totalTracks & totalHours
  - Computed from associated songs
  - totalTracks = songs.length
  - totalHours = sum of all song.duration (in hours)
  - Recalculate on: album create, update, song added/removed

[BL-15] Playlist totalTracks & totalHours
  - Same calculation pattern as album
  - Recalculate on: playlist create, update, song added/removed

[BL-16] Song Deletion Cascade
  - On delete song: remove song from all playlists (many-to-many)
  - On delete song: update album totalTracks and totalHours if song belonged to album

[BL-17] Playlist Deletion Cascade
  - On delete playlist: remove playlist from all users' savedPlaylists
  - On delete playlist: remove playlist-song associations

[BL-18] Album Deletion Cascade
  - On delete album: delete ALL songs in that album

[BL-19] Artist Deletion Cascade
  - On delete artist: remove artist from all songs' artist list
  - On delete artist: remove artist from all albums' artist list
  - Do NOT delete songs or albums when deleting artist

[BL-20] Premium Payment Flow (VNPay)
  1. User calls GET /v1/payment/vn-pay?premiumType=1-month
  2. Get current user from JWT
  3. Map premiumType to amount:
       "1-month"  → 30,000 VND
       "3-month"  → 79,000 VND
       "6-month"  → 169,000 VND
       "12-month" → 349,000 VND
  4. Build VNPay payment params (vnp_Amount, vnp_TxnRef, etc.)
  5. Sort params alphabetically
  6. Generate HMAC-SHA512 signature with VNPAY_SECRET_KEY
  7. Build redirect URL
  8. Return VNPayResponse { code: "ok", paymentUrl: "..." }

[BL-21] VNPay Callback Flow
  1. Receive callback params from VNPay
  2. If responseCode == "00" (success):
       a. Get user by email from params or token
       b. Calculate premiumExpiryDate based on premiumType
       c. Set user.premiumStatus = true
       d. Set user.premiumExpiryDate
       e. Replace user roles with [PREMIUM] role only
       f. Save user
       g. Send payment confirmation email
  3. Return PremiumResponse

[BL-22] Playlist Creator Assignment
  - On playlist create: automatically set creator = currently authenticated user (from JWT)
  - Creator cannot be changed after creation

[BL-23] Search Functionality
  Search format: array of strings like ["name~Rock", "listener>1000", "duration<200"]
  Operators:
    ~ : contains (LIKE %value%)
    > : greater than
    < : less than
  Combine with AND logic across criteria
  Build TypeORM QueryBuilder dynamically from criteria list

[BL-24] Pagination
  - Default: page=1, size=10, sortBy="id"
  - Response always includes: page, size, totalPages, totalItems, items
  - All list endpoints support pagination

[BL-25] Scheduled Task: Refresh Token Cleanup
  - Cron: daily at midnight (0 0 * * *)
  - Delete all RefreshToken records where expiryDate < now

[BL-26] Scheduled Task: Premium Expiry Check
  - Cron: every hour
  - Find all users where premiumStatus=true AND premiumExpiryDate < today
  - Set premiumStatus = false
  - Downgrade role from PREMIUM back to USER

[BL-27] Scheduled Task: Verification Code Cleanup
  - Cron: every hour
  - Delete all VerificationCode records where expirationTime < current time in minutes

# SECTION 13: MIGRATION NOTES & SPECIAL CONSIDERATIONS
# ============================================================

[NOTE-01] JWT Algorithm
  - Spring uses Nimbus JOSE JWT with HS512
  - NestJS: use jsonwebtoken with algorithm: 'HS512'
  - Ensure same key format (same JWT_SIGNER_KEY env var)

[NOTE-02] Date Handling
  - Spring uses LocalDate (date only, no time)
  - NestJS: use Date type with TypeORM @Column({ type: 'date' })
  - Serialize as ISO date string (YYYY-MM-DD) in responses

[NOTE-03] Many-to-Many Relationship Management
  - TypeORM requires explicit cascade settings on ManyToMany
  - Use cascade: ['insert', 'update'] carefully
  - Junction tables match exact names from Java: song_artist, album_artist, etc.

[NOTE-04] Counter Increments (Race Condition)
  - Use TypeORM increment() method for atomic updates
  - Example: repo.increment({ id }, 'listener', 1)
  - Do not fetch-then-save for counter updates

[NOTE-05] Transaction Management
  - Use TypeORM DataSource.transaction() or @Transactional from typeorm-transactional
  - Required for: registration (save user + save refresh token), payment callback, playlist deletion

[NOTE-06] VNPay Signature
  - Algorithm: HMAC-SHA512
  - Node.js: use crypto.createHmac('sha512', secretKey).update(data).digest('hex')
  - Params must be sorted alphabetically before signing

[NOTE-07] MapStruct Equivalent
  - No direct equivalent in NestJS
  - Use class-transformer's plainToInstance()
  - Or write manual toResponse() methods in services

[NOTE-08] Cloudinary Duration Extraction
  - When uploading video/audio, Cloudinary returns duration in response
  - Store as seconds (double)

[NOTE-09] Scope/Authority in JWT
  - Replicate Spring's scope building: space-separated string
  - Format: "ROLE_USER ROLE_PREMIUM CREATE_SONG DELETE_SONG ..."
  - Parse in guard: split by space, check ROLE_ prefix for role, others for permissions

[NOTE-10] Context Path
  - Original: /mymusic (Spring context path)
  - NestJS: app.setGlobalPrefix('mymusic')

[NOTE-11] Pagination (1-indexed)
  - Spring PageResponse uses 1-indexed pages
  - TypeORM findAndCount uses 0-indexed (skip/take)
  - Convert: skip = (page - 1) * size

[NOTE-12] Soft Delete
  - Not used — hard deletes only
  - Manage cascade manually in service layer

[NOTE-13] Email Templates
  - Original uses Thymeleaf HTML templates
  - NestJS: use handlebars or pug templates with @nestjs-modules/mailer
  - OR use inline HTML strings

[NOTE-14] Database Seed Data
  - Roles (USER, PREMIUM, ADMIN) and initial permissions need to be seeded
  - Create a seed script or use TypeORM migrations with data seeds

[NOTE-15] EAGER Loading Equivalent
  - Spring uses fetch = EAGER on some relations (song.artists, album.artists, album.songs)
  - TypeORM: use relations: ['artists'] in find options, or eager: true in @ManyToMany
  - Be careful with N+1 queries — use QueryBuilder with leftJoinAndSelect

[NOTE-16] Search with Specification Pattern
  - Spring uses JPA Specification (Criteria API)
  - NestJS TypeORM equivalent: QueryBuilder with dynamic where clauses
  - Parse search strings ["field~value", "field>value", "field<value"]
  - Build WHERE conditions accordingly

[NOTE-17] Swagger Availability
  - Must be accessible without authentication
  - Path: /swagger-ui (or /api-docs)

[NOTE-18] API Response Wrapping
  - All responses wrapped in ApiResponse { code, message, result }
  - Implement NestJS interceptor to wrap responses automatically
  - On exception, filter returns same structure with null result
